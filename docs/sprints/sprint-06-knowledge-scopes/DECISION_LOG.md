In storage, `scope: common` is canonical; **`scope: global` (the existing tested memory payload value) is accepted as an alias of `common`** — never a breaking rename of the proven `claude/memory` payloads. Apex's "Shared" stays the marketing-surface synonym for Common in microcopy; the data/field value is `common`. | Product | The user said "common (shared across all projects) vs project-level". The codebase ships `scope: project\|global` already tested in `claude/memory/test/{store,recall}.test.ts`; aliasing avoids breaking those payloads while giving the user the word they used. One canonical value (`common`) keeps the recall filter honest; the alias is read-compatibility only. | /po | 2026-06-09 |
| D-011 | **A project declares its stack via project-local config, not the registry.** The stack/kind taxonomy lives as front-matter tags on each knowledge doc (`stack`, `kind`, `scope`); the **project's own declared `stack` (+ optional `domain`)** that recall matches against is read from the project-local `.aidevteam/config.json` (the same file `embedderConfigured` already reads), with sensible auto-detection from the analyzed stack chips as the default and a manual override. Defaults when a doc omits tags: `scope:project`, `stack:any`, `kind:context` (safest = least sharing). | Product | Keeps the stack declaration **per-project and file-based** (no registry-schema change, no new global store), reuses the config file the hub already reads, and the analyzer already detects the stack (the home cards show stack chips), so auto-detect is free. `any` as the wildcard makes a research/no-stack project see only `common+any`, matching research AC-K6. `/arch` confirms exact placement + the precedence (declared override > auto-detected). | /po | 2026-06-09 |
| D-012 | **The mem0/OpenMemory interpretation-check Q&A adapter is a FOLLOW-ON slice (ADT-236), not the core of this chunk.** ADT-234 (scope/tag model + rename) and ADT-235 (the `/kai` propose-inbox) are the must-ship core on the file default. ADT-236 is ticketed now (so it is not lost) but explicitly deferable; it is the only egress surface and keeps its own HARD SECOPS gate. | Product | The user's headline asks — rename, scoped knowledge, cross-type sharing, and the propose→approve inbox — are all satisfiable on the file default with no external service. | D-013 | **Scoped/common knowledge lives in the project vault so BOTH `readKb` and the memory hooks see it, split by scope on disk.** Project-scoped notes stay in the existing first-existing KB dir (`docs/` → `kb/` → `.aidevteam/kb`, the dir `readKb`/`addKbNote` already use) with `scope: project` front-matter. **Common notes live in a single shared vault dir resolved the same cascade as workflow/config (`~/.aidevteam/kb-common/` by default), surfaced into every project's "Common" view** by the projection, and carry `scope: common` front-matter. Front-matter as the source of truth keeps the file self-describing (Obsidian-editable per D-009) and survives a move between vaults. `/arch` confirms the exact common-vault path + the read-merge + the containment rule for the new user-level write target. | /po | 2026-06-09 |
| D-014 | **`/kai` proposals are a PENDING store, never written into the recallable vault until the user approves; recall precedence = more-specific scope wins (project overrides common).** A proposal is stored with `status: pending` in a propose-inbox area distinct from the live vault; only an explicit user **approve-as-common / approve-as-project** writes it into the corresponding vault with `status: approved-*`; **reject** retains it for audit (`status: rejected`), never recalled. When a `common` item and a `project` item conflict for a project, both surface but the **project-scoped item is marked as taking precedence** (per research AC-K5). | Product | This is the load-bearing trust contract Apex/Anna both flag: propose ≠ apply, the human is the gate (mirrors `/kai`'s existing SKILL-update discipline — it already never auto-applies). A separate pending store keeps model-authored (untrusted) content out of the recall path until approved (the SECOPS hinge for ADT-235). "Project overrides common" is the least-surprising conflict rule (the more specific scope is the user's deliberate local override). | /po | 2026-06-09 |
