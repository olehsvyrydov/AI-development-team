# Decision Log - Sprint 10 (Ecosystem)

**Last Updated:** 2026-06-13

## Decisions

| ID | Decision | Category | Rationale | Approved By | Date |
|----|----------|----------|-----------|-------------|------|
| D-1001 | **Public-git install = the 2-command marketplace flow** (`claude plugin marketplace add <owner/repo>` → `claude plugin install dart@dart`), proven against a FRESH CLONE of the public repo — not the local working tree. | Product | Claude Code's marketplace accepts a public GitHub `owner/repo` or git URL, so no clone is needed. The in-repo `.claude-plugin/{plugin.json,marketplace.json}` already ships; this is distribution, not new code. It also operationalizes D-004's "separate-marketplace / public distribution is a Phase 2+ concern once the plugin is proven." | /po | 2026-06-13 |
| D-1002 | **Do NOT spec an npx / `npm install` one-liner for the plugin.** npm is only a marketplace *source* (an alternative to git for the marketplace entry), not an install path for a Claude Code plugin; nvm is irrelevant. | Product | Grounded in current CC docs. Claiming a non-existent install path would be a false promise and a support trap. The install doc states this explicitly. | /po | 2026-06-13 |
| D-1003 | **Memory/overlay stays env-only and OFF by default**, and the install docs name the exact env vars (`OPENMEMORY_BASE_URL`, `OPENMEMORY_API_KEY`, `MEM0_API_KEY`). | Product / Security | Carries the sprint-08 posture (egress disclosed, secrets env-only) into the public-install story so a fresh install leaks nothing and discloses egress honestly. | /po (+ /secops note) | 2026-06-13 |
| D-1004 | **The Kiro adapter is CODEGEN over the SAME Core/skills/workflow/MCP — not a re-implementation of DART semantics.** It emits Kiro-native config (mcp.json + steering + agentSpawn/userPromptSubmit hook shims), bundled for kiro-cli as one custom-agent JSON; the IDE works via MCP + `always`-steering. | Architecture / Product | Kiro natively supports all three DART surfaces, so semantics need not be forked: the MCP server is reused as-is (zero server change), hook LOGIC is reused (same STDIN-JSON/STDOUT-context model, only registration differs), and steering is the analog of the digest + agent-team skills. This realizes the parked BL-06 (Kiro adapter, Phase 2) without a second engine. | /po (+ /arch to ratify) | 2026-06-13 |
| D-1005 | **kiro-cli is the first Kiro target; the IDE is secondary** (MCP + `always`-steering). | Product | The CLI custom-agent JSON bundles MCP+hooks+steering in one file (a clean plugin.json analog) and `agentSpawn`/`userPromptSubmit` map cleanly to our SessionStart/live-directive hooks; the IDE session-start injection is weaker, so it follows. | /po | 2026-06-13 |
| D-1006 | **Kiro adapter gaps are recorded and accepted, not blocking:** no PreCompact-equivalent hook (per-turn hook compensates); IDE session-start less explicit than CLI agentSpawn; SSE transport undocumented → stdio/localhost-HTTP only. | Architecture | DART is already stdio; the per-turn hook already compensates for missing compaction hooks. Documenting the gaps keeps expectations honest and the scope bounded. | /po (+ /arch) | 2026-06-13 |
| D-1007 | **The Kiro adapter SECOPS gate is HARD (safety-override)** because it generates config that registers an MCP server + hooks inside another tool. The generated config must be opt-in, no-clobber (never overwrite a user's existing `.kiro` config), no-secret, no-exec (recorded-only posture), stdio/localhost trust only — each proven by a negative test. | Security | The adapter widens DART's blast radius into Kiro's trust surface; it inherits the plugin's plugin-packaging posture and must prove it the same way (the write/leak that must NOT happen does not happen). | /secops | 2026-06-13 |
| D-1008 | **The hub control-plane SDK is DEFERRED behind an explicit trigger**, not built now. The MCP server + hub HTTP API already are the agent-facing SDK, and the Claude Agent SDK already covers embedding DART in a custom agent (documented recipe instead). The only SDK worth building is a thin typed TS HTTP client for non-LLM tooling/CI callers. | Product / Architecture | Building it before a second consumer exists is premature abstraction. Trigger: a SECOND consumer (the Kiro adapter or a CI step) starts copy-pasting hub-API client code. Marked `stage: deferred` in the ledger so it is not started early. | /po | 2026-06-13 |
